# 加权计算、状态与策略复查修复

候选 `0.4.1rc37`，计算语义 `42`，独立 Python 包的边界不变。
本次复查从干净提交 `039a0eaf99b2c3bc74d81bff6698e3940b83c123` 开始。
原 4,966 项测试全过，但新增反例复现了下面的问题。

## 行为修复

- WMA、linreg 的历史窗口不再依赖整个未来片段的均值。固定 binary64
  精确滚动和在最后一步舍入；period=1 保留输入值。
- ALMA 使用无进位整数多项式卷积，避免整段浮点 FFT 的未来污染。
  按窗口独立 Fraction 参考验证；没有放宽 native 捕获的数值容差。
- 增量 WMA、VWMA 在巨大样本离开窗口后恢复正确的有限小量值；HMA
  的组合与 local/state/replay 续算保持一致。缺失窗口和预热规则保留。
- 参数不可变分类限定精确 builtin 类型；带可变属性的 scalar subclass
  和 slots 图不再绕过 preview 隔离。恢复比较的是受支持参数的结构图，
  包括数值、属性、别名和环，不调用用户 `__eq__`。
  带用户类型的 scalar subclass 支持受控本地快照；portable 导出明确拒绝
  无法完整重建的类型，避免降成普通数字后丢掉属性。普通可表示的 NumPy
  标量在 codec 中规范化，caller params 的既有类型准入范围不因此扩大。
- 空会话首次查询结果与 seed、preview、closed 共用 context 初始化，
  保留调用方选择的 trace。
- 批量无订单策略的 equity 从配置资本开始；后续配置先完整规范化，
  再在临时状态回放，成功后统一采用 equity、position、orders、report。
  batch/incremental 共用数值准入及配置契约，拒绝必填量的 NaN/Infinity。
  可选策略参数保留 `None` 和真实 `na` 的省略含义。
- `input.float`、`input.price` 的默认值及覆盖值必须有限；float 的 min/max/
  step 元数据也必须有限。非法覆盖值不再借 NaN 绕过边界。
  所有输入声明在验证成功后才发布 schema；失败重试不会消耗参数名并绕过
  原覆盖值。交叉复核发现的这个旧问题也有逐类型恢复回归。
- POSIX 调用方 alarm handler 抛出的异常被脚本捕获后，仍重新设置剩余
  的本地期限；一次性和周期 alarm 的异常身份及退出后剩余计时保留。

## 性能与结构

实测工作次数，避免将绝对耗时混入算法复杂度结论：

| 路径 | 数据规模 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| 默认无限预算下 varip 新建计量 | 256/512/1024/2048 个标量 | 65792/262656/1049600/4196352 | 512/1024/2048/4096 |
| 删除独立 linefill 的父线 | 128/256/512 个填充 | 8256/32896/131328 次桶扫描 | 恢复后一次重建，128/256/512 次；常规删除只遍历关联填充 |
| 仅最后一项缺失的 percentile | N/P=1000/250、2000/500、4000/1000 | 187500/750000/3000000 次比较 | 250/500/1000 |

有限 state payload 配额仍重新检查已有嵌套变异，不宣称该路径线性。
linefill 反向索引是可重建派生数据，portable snapshot 只保留权威字典类型
及条目。typed decode 先保留图身份，再重建索引，兼容条目循环和脚本保存的
桶别名；普通字典 fallback 首次使用重建索引。畸形条目在采用恢复状态前
拒绝。删除事件顺序及 preview 不提交行为有回归覆盖。
23 个批量 line/linefill 函数移到专门工厂，绘图 namespace 改为显式绑定，
去掉 `locals()` 拼接；策略配置/数值规范化共用 typed 契约与只读回放配置视图。
约 700 行策略回放主体仍需后续拆解，本轮没有宣称消除全部架构债务。

ALMA 窗口 1000、10k/20k/40k 数据的受控三次中位数：普通正负输入
0.0744/0.1597/0.4077 秒，Python traced peak 3.36/6.76/13.52 MB。
混合正负 `1e308` 与 `1e-300` 时为 4.019/8.211/14.391 秒、
11.57/19.36/34.94 MB。极端位宽的精确计算有明显绝对成本；这些临时
分配数据不是 RSS，也不代表任意百万级数据的容量资格。

## 快照和验证

语义从 41 升至 42，package/wire 版本身份保持分离。真实旧状态由干净
旧提交导出源码、构建 rc36 wheel 并独立安装生成，保留在
`tests/golden/audit_semantics_v41`。provenance 包含提交、wheel SHA256、
脚本/数据/结果/state/replay 哈希。旧结果中 WMA 尾值为 2、VWMA 为 0，
新语义均为 1。旧 state/replay 必须在构造会话前拒绝，并提示从权威 OHLCV
重建；同语义 local/state/replay 支持 preview 隔离与继续执行。

新增 401 个回归：数值 60、参数/状态 61、策略 145、输入/超时/绘图/升级
87、参数可移植性 48。完整收集 5,367 个测试，以三个不重叠模块分片验证；收集及源码哈希
保留在 `.tmp/audit-fix-20261004/`。专项记录与原反例失败日志分别保留在
`.tmp/audit-weighted-repair-20261004/`、`.tmp/audit-state-repair-20261004/`、
`.tmp/audit-strategy-repair-20261004/`。

最终完整结果：三个不重叠分片各 1,789 项，全数通过，耗时分别
525.25、684.70、437.55 秒；总共 5,367 个 distinct node IDs，冻结源码
哈希没有变化，没有测试警告。早期因交叉复核暂停的运行单独保留，
没有把那些部分结果加进最终计数。

独立安装 rc37 wheel 后，401 个新增回归及 6 个原有 timeout 正控（合计
407 项）全过，全部已加载的包模块都来自该安装目录。99 个包内 Python
文件与当前源码逐字节一致。真实独立 venv 另通过 9 个使用流程、55,075
个结果比较点。Ruff、compileall、project-status、diff-check、strategy
scaffold、三组 capture 检查、build、Twine、离线 package smoke 均通过。
最终 performance smoke 的 14 个检查以默认 9 repeats 全过，稳定性
smoke 的 16 个会话各 256 bars 全过。WSL 真 POSIX alarm 的一次性/周期
调用方异常均未丢掉本地 0.23 秒期限，实测约 0.2306/0.2304 秒。

这是本地 Windows 候选验收，POSIX helper 有额外 WSL 证据，不代表完整
跨平台发布矩阵或任意规模的资源资格。本轮没有 commit、push 或发布。

当前 rc36 wheel 与 rc37 的同一 native 证据配对，131,586 个 active cells
的 11,748 个差异逐条相同，新增/修复差异位置均为 0；TA sparse 捕获的
144 个已披露差异也不变。7 个 workload-mode 的 30 列只有约 `1e-14`
