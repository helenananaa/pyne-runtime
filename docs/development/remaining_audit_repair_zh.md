# 剩余架构、性能与正确性修复

本轮候选为 `0.4.1rc36`，计算语义为 `41`。在 rc35 修复上继续处理了
可以复现的问题，未纳入 TradingView 数值兼容差异。

| 问题及触发 | 修复 |
| --- | --- |
| 历史恢复接受不同时间轴的同脚本快照，随后 advance 失败 | 恢复前核对已提交、保留时间线及当前 bar 与固定历史前缀的一致性。 |
| 伪造记账可绕过恢复时输出、状态和窗口预算 | 核对真实输出、事件、表格、策略日志及窗口下界；重新计量独立图的状态 payload 后再检查预算。TA 核对真实队列长度、容量和组合子对象类型。 |
| 入参扩展字段与已提交状态共享，preview 能污染状态；回放记录的是回调修改后的数据 | 回调前独立复制完整输入图，并记录回调前数据；不支持复制的对象在改变状态前拒绝。保留同批输入内的共享身份。 |
| 同线程同 key 的会话 factory 重入，等待自己的创建事件 | 明确拒绝同 key 递归创建；不同 key 与其他线程仍可正常创建、等待。 |
| 缓存大幅缩容逐条全表扫描，累计平方级工作 | 批量驱逐一次按原 LRU 顺序稳定排序；单条正常驱逐保留原路径。 |
| snapshot 把共享集合重复展开，并把同一个子对象克隆成多个对象 | 使用迭代图遍历与单次 memo，保留内部共享并与原图隔离。 |
| 深层 connected slice 的长度、读取和写入耗尽递归栈 | 迭代解析切片存储窗口，保留父窗口变化和写入连接。 |
| 深层集合 deepcopy 使正常 preview 和 restore 失败 | 先迭代分配完整集合存储图，再填充；复用调用方 memo，保留函数、全局值与集合别名。 |
| 明确导出、导入和取值结果的嵌套容器别名可反改原对象 | 在 collector 导出及 PyneResult 导入、导出、series 取值边界复制嵌套数据；普通公开可变字段仍可直接编辑。 |
| latest 读取最后值却复制整个 series 历史 | 直接查找末项并只复制返回值，避免与历史长度成比例的额外复制。 |
| 零维 NumPy plot 数据触发不可迭代、不可 reversed 错误 | 将零维数组按已有标量路径归一化，不更改数值舍入规则。 |
| lower_tf 返回数组漏绑显式大小、深度限额 | 分组物化前检查大小，返回数组保留选定限额及后续变异检查；batch 同样检查分组。 |
| 字段先读取、稍后切换浮点策略后再求 thunk，派生预热异常时机变化 | 保存第一次字面字段读取时的策略；延迟预热按该策略执行，首次 thunk 保留当前策略。 |
| 自定义元数据方法被字段快路径跳过或未绑定时间线 | 自定义元数据走完整上下文，保留 Python 方法调用及绑定行为。标准元数据字段仍用索引投影。 |
| 直接进程入口接受 NaN、Infinity 或负超时 | 所有显式超时覆盖使用 settings 的有限、非负校验，在分配进程资源前拒绝。 |
| 进程结果不可序列化，队列后台丢失结果，只报告退出码 0 | worker 先序列化一次并传输字节，明确返回 `PYNE_PROCESS_SERIALIZATION_ERROR`。 |
| 进程、队列在成功、异常、启动失败或中断后未明确关闭 | 统一 finally 清理；超时和残留 worker 经过终止、必要时强制终止，再关闭句柄和队列。 |
| 嵌套或已有 POSIX alarm 被覆盖、取消 | 组合更早的期限，保留调用方处理函数、周期计时及扣除已消耗时间后的剩余额度。 |

真实 rc35 /40 旧工件保存在 `tests/golden/audit_semantics_v40`，来自上一轮
独立安装、验证过的 wheel，未重标快照语义。旧脚本的共享 snapshot/history
身份输出为 0，新版为 1；语义不兼容必须拒绝并从权威 OHLCV 重建。
local、typed-state、replay 的同版恢复、preview 隔离及后续计算均有回归。
包版本、计算语义和 wire-format 身份保持分离。

纯 Pyne 集合存储图、共享对象和切片使用迭代处理；普通 Python 叶对象仍
遵循其 deepcopy 行为。任意 Python 请求表达式、自定义元数据和没有历史
最终性承诺的供应商仍可能需要完整上下文或重新获取历史。不会自动推断
用户 Python 方法纯度。默认 `None` 仍表示无计算限额，恢复重新计量和缓存
缩容不增加宿主策略，也不把可恢复缓存的容量当成输入计算上限。

配对快照控制中，深度 12 的共享图从 8191 个输出对象、188419 次读取降为
13 个输出对象、13 次读取，且保留共享引用。600 层 snapshot/deepcopy 和
1000 层 slice 从旧版递归失败改为成功。标准字段请求 1024 条控制保持零
历史上下文复制，耗时约 0.336 秒；这些仅是受控工作量或耗时，不能推广到
任意用户 Python 对象与表达式。各配对收据保留旧 wheel 身份及当前源码 SHA。
架构检查器也修正了把标准库绝对 `collections` 导入误认成内部模块的问题，
并增加相对导入与真实包导入的正控。

缓存 5000 条缩至 32 条的混合 LRU、相同时间戳配对中，旧版访问
12,501,972 条键值，新版一次遍历 5000 条并排序。全部 4968 条淘汰序列和
32 条保留记录的顺序与独立稳定 LRU 正控一致，不以耗时作为判断依据。

本轮完成 **4966 项不同测试**的验证，其中新增 **191 项**。三个互不重叠
分组首轮通过 4965 项；唯一失败是旧恢复复制测试把锁对象当作权益记录，
新增格式校验现在会在复制前拒绝它。该用例改为合法 Real 数值、明确抛出
复制错误的对象，继续验证原会话的原子性。相关 131 项重新通过，运行时
源码未改变；原始失败收据保留，不重复累计相关重跑的覆盖数。测试无警告。

独立安装的 rc36 wheel 通过全部 191 项新增回归，以及另外运行的 131 项
历史恢复相关检查；两组存在交集，不相加作为不同测试数。全部 Pyne 导入
来自仓库外安装目录，93 个 Python 文件与资格源码逐字节一致。独立包接受
检查通过 9 个工作流、55,075 个对比点。13 项静态、性能、稳定性、捕获、
构建、分发及包接受门禁均通过；TA 捕获仍有 144 项已披露数值差异，零新增
未披露差异。最终文档检查通过后重建源代码分发包，wheel 保持已安装验证
的原件，并核对分发包内运行时、测试和文档的当前字节。
